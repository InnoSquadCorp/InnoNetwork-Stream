# InnoNetwork-Stream 6.1.1

Status: Ready for release
Release date: 2026-10-09

This is the first stable Stream release, aligned with Network 6.1.1. Publication
is performed by the validated release workflow after the source-bound evidence
and required gates are approved. The ready marker does not assert an existing
tag, completed GitHub Release, or application rollout.

## Release scope

- Core dependency: exact `6.1.1`, published tag revision
  `44e4ca28c50c03f817231a077c0f3bdfdbc859c8`.
- Reviewed 6.x public surface and pre-release migrations: [API Stability](../../API_STABILITY.md).
  Four modules, the aggregate product, six macros/manual equivalents and existing
  Apple deployment floors are retained.
- Bounded HLS parsing, steering, AES keys, offline operations, cancellation,
  coherent rolling DVR checkpoints and timeline expiry.
- Direct-media Offline entries preserve the localized primary media playlist;
  multivariant inputs and legacy packages retain their supported behavior.
- AVFoundation playback/background integration, application-owned FairPlay
  provider contracts, decoded audio and bounded metadata coordination.
- Apple conformance collection uses real public-SDK Offline/DVR outputs for TS
  video, fMP4 video and fMP4 audio, compatible JSON/report 1.3 and fail-closed
  blocking/unsupported-format checks. Raw warnings remain visible.

## Validation and publication boundary

The release preparation includes [PR #11 exact-head CI](https://github.com/InnoSquadCorp/InnoNetwork-Stream/actions/runs/37941806451)
at `005ff03ba0f5ba925302b2b1dbbddf250874d0e1`, merged into canonical main
`7f29bf5212e696e1e6f0237cd1319d8a405b775f`. Its 14 jobs passed both Xcode lanes,
five Apple platforms, API/DocC, CodeQL, actual six-case SDK generation and macOS 27
AVPlayer/audio/LL-HLS/DVR runtime smoke. Later source/document commits require
their own exact-candidate validation; this historical PR run is not final
canonical-main publication proof.

The final source commit and fingerprint are recorded in
`ReleaseEvidence/apple-hls/manifest.json`. An authorized maintainer must review
the actual tool execution, dependency/fixture inputs, raw results and warnings,
then separately approve the exact manifest digest and reviewer identity. The
full release preflight and nonpublishing Release workflow must succeed on exact
canonical main before the annotated `6.1.1` tag is created.

Application-owned physical-device background restoration, protected-storage and
FairPlay-provider scenarios remain **NOT RUN** until the consuming app owner
supplies an authorized app/device/entitlement/provider context and records the
applicable results. SDK tests, clear-content conformance and macOS runtime smoke
do not certify these device or DRM-provider behaviors. See
[Device acceptance](../DEVICE_ACCEPTANCE.md).

After publication, verify a clean external consumer resolving both published
Stream and Core `6.1.1` tags. Historical commit/path consumers do not replace
that installation check.

Follow [Release Policy](../RELEASE_POLICY.md),
[local evidence instructions](../LOCAL_HLS_EVIDENCE.md) and the
[release execution checklist](../RELEASE_PREPARATION_6.1.1.md).
