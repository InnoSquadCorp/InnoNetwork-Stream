# InnoNetwork-Stream 1.0.0 Release Notes

Status: Draft (unreleased)

Release date: TBD

This draft is not a published release and must not be used to create a
`1.0.0` tag.

## Highlights

- Adds `@HLSOfflinePackageDefinition` and explicitly owned offline package tasks
  with independent bounded progress/receipt observation. Shares and bounds
  Steering manifest loads, anchors TTL/Retry-After after receipt and supports
  HTTP-date/zero waits. See [iterative verification](../ITERATIVE_HARDENING_2026_10_02.md)
  for fresh local evidence and the unchanged external release boundaries.
- Adds the Draft macro-first `@HLSDownloadDefinition` workflow and validated
  effective settings. Explicit download handles separate operation cancellation
  from bounded progress/result observation; committed output wins late cancel.
- Fixes oversized LL-HLS history allocation, finite authoring-duration traps,
  intermediate variable expansion, shared steering waiter cancellation and
  persistent FairPlay stage cancellation. The ten-slice macro-first redesign
  is locally implemented; supported remote/toolchain/adopter gates remain open.
  See [its execution plan](../MACRO_FIRST_REDESIGN.md).
- Adds declarative Live, DVR, playback and optional catalog workflows;
  discriminated parser/planning models, independent bounded observation,
  staged app-owned metadata, structured failures and redacted incidents.
- Gates distinct semantic API signatures and provides reverse-dependent local
  feedback while preserving complete CI/release checks. New APIs remain Draft.

- Moves `InnoNetworkHLS`, `InnoNetworkHLSLive`,
  `InnoNetworkHLSAVFoundation`, and `InnoNetworkHLSAudio` into an independently
  versioned package without changing module imports.
- Uses InnoNetwork 6 public bounded-transfer, retry, URL-admission, trust, and
  observability contracts instead of package-internal implementation details.
- Preserves bounded playlist, key, segment, offline-package, and live-DVR
  resource handling.
- Keeps FairPlay credentials, entitlements, and license-server policy under
  the consuming application's ownership.

## Dependency migration

Applications move the four HLS products from the InnoNetwork package
declaration to InnoNetwork-Stream. See
[Migrating from InnoNetwork](../MIGRATION_FROM_INNONETWORK.md) for the exact
manifest diff and clean-checkout validation requirements.

The root and external-consumer manifests pin published InnoNetwork `6.1.0`
exactly, at tag commit `79ff9f535a0a15ad8b52ce49cb5a4b1ea1dfec16` in the root
lock. Stream's direct SwiftSyntax dependency is aligned to Core's 604.0.x range.
CI and CodeQL verify the published graph and reject local overrides or branch
locks. Previous 6.0.0 and branch evidence remains historical. See the
[Core dependency contract](../CORE_DEVELOPMENT.md).

credentials, entitlement context, and a license server. The release must keep
the deterministic adapter and workflow tests green even when live acceptance
credentials are unavailable.
